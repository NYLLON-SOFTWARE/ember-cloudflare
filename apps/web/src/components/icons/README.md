# Icons

Every icon Ember draws is Iconoir's, from its 7.12.1 release, as the project's owner chose, picking one
for each place, with three exceptions: the icons people choose for rooms and the rail, from the icon
pickers' catalog; the setup help's picture of Chrome's View site information button, which shows what
Chrome draws there; and the brand images. Import icons from this folder, never from `lucide-react`:
`icons.test.tsx` fails `pnpm test`, and so CI, if any other file does, and it checks every icon here,
every icon the formatting toolbar and the error pages draw, and the copies in `apps/web/public`, against
Iconoir's files in `iconoir/`.

| Module | What it holds |
|---|---|
| `iconoir.tsx`, `iconoir/*.svg`, `iconoir/solid/*.svg` | Iconoir's icons, pinned to 7.12.1 (24px grid, 1.5 stroke, `currentColor`), each named `iconoir-<name>`, or `iconoir-<name>-solid` for a solid one, as Iconoir's stylesheet names them. `iconoir/` holds their files from the `iconoir` package's `icons/regular/`, and `iconoir/solid/` those from its `icons/solid/`, byte for byte, with Iconoir's license. A few have no component: the formatting toolbar's, which `workspace/rich-text-editor.css` paints over Lexxy's own, and the error pages', which `apps/web/public/404.html`, `422.html` and `500.html` draw inline |
| `campfire.tsx`, `campfire/external/sliders.svg` | Campfire's picture of Chrome's View site information button, for the notification setup help, copied byte for byte from once-campfire's `app/assets/images/` at `90b3300`, drawn as a black `<img>` inverted where the background is dark and named by its `aria-label` |
| `lucide/catalog.json`, `lucide/LICENSE.txt` | A catalog of Lucide's 1,869 icons (`{name, label, svg}`, 991 KB), generated from lucide-static 1.53.0, which `catalog.test.ts` checks the pickers' Lucide icons against, with Lucide's license |
| `picker/catalog.json` | Every icon a room can have: the icon pickers' catalog of Lucide's 1,869 icons, drawn as `lucide/catalog.json` draws them, and Iconoir 7.12.1's 1,671, regular and solid, under its license in `iconoir/`. Each has its label, its collection, the tags search finds it by and, for the 120 suggested for rooms, what a room with it is for (`roomLabel`), and the catalog orders them once for rooms and once for navigation (3.2 MB). `ROOM_ICON_NAMES` in `@ember/protocol` lists their names and `room-labels.ts` their rooms' labels, both generated by `catalog.test.ts`. `vite.config.ts` writes each icon to a file of its own, `/lucide/icons/<name>.svg` or `/iconoir/icons/<variant>/<name>.svg`, and a picker loads the whole catalog when it first opens |
| `room-icon.tsx`, `room-icon-label.ts` | A room's icon, from its own file, as a mask in the color of the text around it, or `#` for the default, and what the pickers call it, crediting Iconoir's |

The brand images live in `apps/web/public`, with the icons the web app manifest lists.
`logos/app-icon.png` and `logos/app-icon-192.png` are Ember's icons: the home-screen icon and the
installed app's. `shortcuts/plus.svg` and `shortcuts/user.svg` are Iconoir's, byte for byte, for the
installed app's New chat room and My profile shortcuts. The favicon,
`logos/app-icon-48.png`, is the same image scaled from 512px down to 48px: browsers fetch the favicon
while the page loads, and in Lighthouse the 121 KB original delayed a room's largest paint by about
390 ms on mobile and 80 ms on desktop. For the same reason, while the workspace has a logo the app
points the favicon at the logo's 192-pixel variant, and only the Apple touch icon at its 512-pixel
one (`hooks/use-account-logo.ts`).
`ember-icon.png` is Ember's flame, on the rail and the sign-in card, scaled from 1254px down to 192px,
so the page doesn't load 595 KB for a 44px mark.
`browsers/` holds Campfire's browser logos, byte for byte, for the Worker's "Upgrade to a supported web
browser" page, and `globe.svg` is Iconoir's globe, byte for byte, for that page's translation button.
They're static files rather than icons here because that page is plain HTML from the Worker, which
old browsers can read without the app; an `<img>` draws Iconoir's lines black, so the page inverts the
globe in dark mode. Whatever goes in `public` is also left out of `run_worker_first` in
`wrangler.jsonc`, as these are, so it's served without the Worker.

## Adding an icon

Use Iconoir's, from the release `iconoir.tsx` names, and ask the project's owner which, as they chose
each one there is. Copy the icon's file from that release's `icons/regular/` into `iconoir/`, or from its
`icons/solid/` into `iconoir/solid/`, byte for byte, then draw it in `iconoir.tsx` with the file's
shapes and attributes, under the file's name in PascalCase (`multi-bubble.svg` is `MultiBubble`, and
`solid/star.svg` is `StarSolid`), spreading `LINE`, `DOT`, `ROUND_ENDS` or `OUTLINE` where a shape's
attributes are one of those sets, and `icons.test.tsx` compares the two. An icon is `aria-hidden`
unless it's given an `aria-label`, as the setup help's pictures of buttons are.

The icons draw in the color of the text around them, so a button that's white on red or reversed
sets its own text color (`text-white`, `text-primary-foreground`), and a faint picture its opacity.
Size an icon for its place (the rail's are 22px, sidebar headings 15px, message actions 16px, composer
buttons 18px), setting both its width and its height, since an icon is 24px square until it's told
otherwise. Adding a shadcn/ui component brings `lucide-react` imports with it, so swap those for icons
from here.

## Updating the catalogs

`catalog.test.ts` holds the SHA-256 hash of `picker/catalog.json`, `lucide/catalog.json` and
`lucide/LICENSE.txt`. To change a catalog, replace its file and put its new hash there; moving to
another `lucide-static` changes both catalogs, since the picker's holds Lucide's icons too. Then
`pnpm --filter @ember/web exec vitest run catalog --update` rewrites the room icons' names in
`packages/protocol/src/room-icons.ts` and their rooms' labels in `room-labels.ts`.
